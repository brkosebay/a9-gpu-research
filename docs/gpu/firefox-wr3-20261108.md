## Urgent W correctness issue

Device receipts: `build/gpu/firefox-hw-webrender/device-r39-4/numeric-{default,bank0}.log`.
Five probes pass; `position-w-no-smooth` fails with3072 bad channels, equally
with default and forced-bank0 allocation. This descendant was not flown.

**Root cause found:** `codegen()` calls `plan_varyings()` **before** `liveness()`.
The old planner tested `V(c, &in->def, 3)->uses`, which is still zero. With
no smooth user varying, it leaves `w_set=0`, so the driver has no W DOUTI,
coefficient sizing or varying-program pointer. Later, after liveness, USC
still emits its native coefficient-set-zero W read. A smooth varying sets W
independently and masks the planning bug, matching the passing device arm.
The driver already emits RHW and r39-4's follow-up handles W-only storage.

90cbc queries `nir_def_components_read()` early and refuses W without smooth
user inputs. That guard is meaningful because it no longer uses the empty
backend counter. W-only, flat-only and noperspective-only negatives plus the
smooth positive pass,19 compiler cases total; step6/7 and corpus270 passed
before that commit was announced. 8882 removes the temporary guard while
retaining the correct NIR query. All four interface fixtures now report
`w_set=1`; the W-only r39-4 interface reported zero. **The proper fix still
requires G5P numeric qualification**, and must not be confused with the safe
refusal cut used by r39-6.

The probe is32×32, outputs `vec4(vec3(gl_FragCoord.w),1)`, and expects
`W=1-(x+.5)/(4*32)-3*(y+.5)/(8*32)` in RGB.3072 equals1024×3; it is consistent
with every RGB channel failing, not evidence for a quarter-frame band. The
aggregate counter alone does not prove the channel distribution. The new
diagnostic probe prints separate R/G/B/A bad counts and first/last RGBA.
Reference first/last pixels are `(253,253,253,255)` and `(98,98,98,255)`.

## Other changes, roots and evidence

A retry after all existing allocation/scheduling attempts splits the live
range of an explicit-LOD sample/fetch: clone the identical NIR read at its
consumers, then rebuild SSA indices, liveness and read groups. Only a
straight-line VS with no storage writes can take it. Descriptor, coordinate,
LOD and texture operation are preserved; no reload from mutable storage,
private frame or larger register mask is introduced. Retries/use fan-out and
the existing program-size limit bound expansion. The existing A9 TPU tuple,
WDF, bank moves and output forms are used unchanged.

**Blend pressure remains:** experiments with scalar IO scheduling, preserved
vertex branches, ALU/expression recomputation, compare-register reserves,
early source release and recipe scratch relocation did not solve both
variants. Those unsuccessful prototypes were removed. An intermediate
uninserted-NIR-source rewrite bug in an expression prototype was diagnosed
with UBSan and fixed before the prototype was removed; no crashing prototype
is in the committed branch. Dense numeric correlation graphs also still
refuse; they are retained in `dense-pressure-boundary/`, not counted as
admitted GPU probes. Pack14 still lacks allocation owner/base/stride/indexing
and lifetime. No guessed private spill ABI or high writable VS bank is used.

**Dual-source:** both optional GL text variants now link and admit. A new
native Apple A9 Metal probe uses `[[color(0),index(0/1)]]` and source1 blend
factors; its ordinary tile/f16 ALU composition is in `apple/dual/`. Our
lowering packs primary colour into halves0..3 and secondary into8..11,
reserves their dwords from body allocation, and uses the existing factor DAG
and native f16 operations. Secondary stores cannot overwrite primary output
bookkeeping or receive primary-only blend rewrites. The fixed input halves
are included in blend scratch occupancy and temp extent. The A9 capability
is max one dual-source attachment. **One runtime file necessarily changes:**
`pvr_physical_device.c` enables that feature/limit for A9, otherwise GL rejects
the shader before PCO. No winsys/VDM file changed. One f16 colour attachment
and four written secondary channels are the currently implemented interface.
Numeric source1 RGB/alpha are distinct and spatially varying; G5P pixels pending.

**General blend + kill + DS writes:** the compiler's unconditional epilogue
refusal predated the driver's PUNCH_THROUGH selection for destination-reading
kill programs. Apple A9 `apple/discard/` independently keeps one `0461` before
SourceAlpha/One general blending with DS attachments. Existing

**Genuinely varying derivatives, partial:** hoist a derivative and its

moved. A new guarded-UBO negative explicitly checks the named derivative refusal. Apple's fresh varying-loop programs
