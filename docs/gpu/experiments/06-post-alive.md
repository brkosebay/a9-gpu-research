## Pending G2 outcome guide

1. **Pass:** runner `stop: done rc=0 reason=type-0-alive`, `alive=1`, no
   failure, a firmware-owned event `type=0` with all eleven raw words.
   IRQ174>0 establishes firmware interrupt delivery; IRQ174=0 with a valid
   polled type-0 still establishes alive but leaves routing open. Continue
   with the separately enabled CL probe, or integrate round 7 next boot.
2. **Arm reset gate fails:** `G2 verify reset actual=...` differs from
   `0000000100000000`, or wrapper GPC/core polls return -110, or FIFO verify
   reports mismatching raw words. Stop at arm; load/release absent. Preserve
   actual/expected values and wrapper/FIFO log. Revisit stream execution and
   Fender transition; do not read a18, change MMU or force guessed clocks.
3. **Arm stalls:** the last `G2 W/poll/raw` or `G2 R R0+00100/00104` marker
   has no matching completion. There must be **no post-arm a18** access in
   this retry. An a18 after arm implies stale integration/binary; check
   payload identity. A lock on the remaining wrapper/reset access invalidates
   that access-state assumption and requires removing/staging it separately.
4. **Load fails:** `command load result=-74` (EBADMSG) before the RAM-verified
   marker, or the supervisor stops at load. Investigate coherent image copy,
   bounds and corruption using CPU memory only. No slave-port fallback.
5. **Release fails/stalls:** last marker is in replayed full FIFO or Fender
   start; no completed release command. Preserve wrapper stream/transition.
   If a poll returns -110, revise the failing wrapper prerequisite. If a
   transaction never returns, a software timeout cannot recover it. No R0
   snapshot or new baseline sample after the transition.
6. **Release returns, no alive:** `G2 no alive event: events=<n> IRQ174=<n>`
   and `command events result=-110`; runner stops at events. With 0/0,
   inspect boot image/config pointer handoff, page-table encoding and the
   still-zero dynamic init policy offline. With IRQs but no event, inspect
   init event pointers/index ownership and ACK routing; IRQ alone is not
   alive. With other event types, preserve the raw eleven words and decode
   that type before changing init. No kick is permitted yet. Round 7 now
   latches this timeout as failed; the pending round-6 kernel does not latch
   the events timeout, so the **runner's failure** is the gate on that build.
7. **Event index invalid:** `G2 invalid event indices <consumer>/<producer>`,
   indices >255, -71 (EPROTO). Investigate pointer/layout/address conversion
   and DMA publication. Do not overwrite indices to zero and continue.
8. **Firmware event fault:** pending round 6 prints
   `G2 firmware fault/recovery event=4|7|8; retain entry, reboot required`.
   Round 7 instead stops on **every type except 0/1**, printing
   `G2 unsupported/fault event=<type>; retain entry, reboot required`.
   Type 6 in particular needs Apple's unsafe slave-stop/recovery branch;
   Linux preserves it instead of issuing those accesses. Decode first.
9. **IRQ storm:** `G2 IRQ174 storm capped; reboot required` after >256 IRQs.
   Handler disables the Linux IRQ without waiting. Preserve count/event
   producer and ADT ACK evidence; audit consume/ACK ordering before retry.
10. **Pre-arm failure:** summary names validate/prepare/wake/id/sample/map
    and later stages are absent. Validation/prepare failures are firmware,
    bounds or allocation issues; wrong ID rejects map; wake/sample can
    still have a hardware access stall. Change only that failing gate.

Every failure means retain the log and reboot before another GPU attempt.

## New-stage failure guide

- DC prepare: out-of-range indices -71; outstanding queues/work -16
  (EBUSY). No entry/kick. Review ownership/index layout before retry.
- DC submit: active-state check -112 (EHOSTDOWN) means firmware parked.
  No kick or speculative restart. Recover Apple's full wake policy first.
  Changed indices/faults stop before publication. A hard lock ending at
  `DC publish ... W R0+00b00` challenges kick accessibility even after alive.
- DC wait: `DC timeout consumer=... producer=... target=...`, -110; retain
  the ring and command. Unexpected consumer/producer -71. Consumption is
  an acknowledgement of transport, not a separate reply event or shader.
- IRQ test: `IRQ delivery timeout`, -110, stops before CL. Inspect AIC
  routing/ACK, not META registers. This injected test cannot identify a
  concurrent IRQ's provenance or prove firmware IRQ generation by itself.
- CL: non-active wrapper blocks the kick; timeout or changed stamp/indices
  retains backing. No park after failure. Zero context/private channel
  composition remains inferred and may be the cause even if DC succeeds.
- Park: nonempty rings/in-flight work stop before hardware. A wrapper poll
  timeout stops after freezing commands (`stopped=1 parked=0 failed=1`).
  No PMGR power-off, direct reset, DMA free or retry follows. Success only
  verifies wrapper GPC=0; complete power-off/DMA quiescence remains open.

No outcome enables COMPUTE, RENDER or live user VMs.
