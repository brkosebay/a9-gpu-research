# A9 CLPC traffic counters and Linux governor design — 2026-11-11

Lane CLPC. No device access, no pushes, no workspace commits. [P] = established by static code; [V] = measured on hardware (only explicitly cited prior work); [I] = inference or proposed design. This lane has no new [V] results.

## 1. Counter provider and register interface

[P] Shared Ghidra target: iOS 16.7.10 j71t `kernelcache.release.iPad6,11_12`. References below are unslid virtual addresses. Read lane SOC [§1](../release/orchard-0.4/lane-soc/README.md) first for the already established policy.

The provider is **AppleS8000MemCacheController**, not an AGX firmware counter and not a userspace IOReport subscription. CLPC resolves `function-amcperfcounters`, constructs `AppleCLPCAMCPerfSampler`, and calls the provider's `AppleS8000AMCPerfFunction` interface. IOReport supplies cumulative reporting, but the provider itself reads MMIO.

| Address | Finding [P] |
|---|---|

| `fffffff00649f0bc` | `AppleCLPCAMCPerfSampler_init`: binds provider and named outputs |
| `fffffff00649f308` | `AppleCLPCAMCPerfSampler_sample`: calls provider vtable +0x80 with counter ID and output pointer |
| `fffffff00642f65c` | AMCPerfFunction dispatch entry; calls MCC sampling routine (entry is not a defined Ghidra function; body contains defined function at `…f670`) |

Its start entry is `fffffff00642d568`, mapped pointer stored at object +0x98. `amc@0` is a different node; do not select it just because of the AMC name. The CLPC CPU sampler maps the **`clpc@2010000`** node's `reg` separately.

### 1.1 Port monitor [P]

- Bank control: MCC + **0x500**; Apple writes **0x11**. The individual meanings of these control bits are unresolved.
- Slot enable bitmap: **0x504**.
- Slot n configuration: **0x508 + n × 0x1c**, six 32-bit words.
- Slot n count: **0x520 + n × 0x1c**, one **32-bit** read/write register.
- Configuration selects port and request class. The driver gives the decoded selectors names in chip match data; it does not import any firmware blob or ADT tunable table.

| Logical CLPC input / Linux event | Physical slot(s) | Byte conversion [P] |
|---|---|---|
| `cpu-read` / `cpu_read` | 0 and 4 | 128 × slot 0 + 2 × slot 4 |
| `cpu-write` / `cpu_write` | 1 | 2 × slot 1 |
| `gfx-read` / `gfx_read` | 2 | 2 × slot 2 |
| `gfx-write` / `gfx_write` | 3 | 2 × slot 3 |

[P] CPU port selection differs from GFX selection; read differs from write. CPU read slot 0 uses a different request-size filter from slot 4. [I] The first term counts line-sized traffic and the second accounts for other transfers. The exact fabric transaction classification is not proven; **do not remove slot 4** or treat each raw tick as a byte. These are MCC-port bytes, not necessarily DRAM-pin bytes after cache effects.

[P] Apple initializes six configuration words for each enabled slot, then writes control and slot mask. Sampling sequence, under an interrupt-disabled lock:

1. Read the slot's 32-bit count.
2. Read the bank enable bitmap.
3. Write enable with this slot's bit cleared.
4. Write zero to the count register.
5. Restore the original enable bitmap.
6. Multiply by the descriptor's scale and add to the cumulative IOReport channel; return cumulative value to CLPC.

[P] There is no hardware sampling window programmed by this path: counting runs while enabled, with software drain/reset at sampling. No overflow interrupt or overflow-status handling appears here. Apple's intermediate sum/product is 32 bits before its cumulative report; Linux widens **before** multiplication.

[I] More than one raw wrap between samples cannot be recovered with this interface. A 2-byte counter's raw wrap represents 8 GiB. Linux drains every 10 ms while sampling; this is comfortably below the wrap period at A9 bandwidth, but prolonged interrupt starvation can still lose counts. Apple reads before disabling, so increments between read and disable are lost by construction. Accuracy must be measured. Zeroing and enable behavior is [P] Apple usage, not a hardware-manual guarantee.

The separate banked AMCX counters use base `0x1c0580 + bank × 0x40000` (bank starting at 1), the same 0x1c slot stride, and a channel count. Independent aggregate memory/fabric totals also use MCC +0x28/+0x2c and +0x30/+0x34. **None of these are touched by this driver.**

### 1.2 CPU stall source [P / unresolved]

`fffffff007a92b78` describes CPU perf events, including `core-cycle` and event **0xea** named `clpc-core-stall`. `fffffff0064997ac` creates the CPU perf sampler through `fffffff0064a0b9c`; `AppleCLPCCPUPerfSampler_init` at `fffffff0064a0a30` builds event selectors/masks from this descriptor table. Its `cpmu-reg-unlock` path accesses the debug/CPMU aperture through the CLPC mappings. This is **CPU PMU telemetry, not an AMC stall register**.

The SOC stall controller at `fffffff006491220` uses the stall metric with a nonzero `core-cycle` gate. The initialization also creates normalized stall/cycle metrics. [I] A Linux `perf_event_create_kernel_counter` pair for cycles and raw 0xea is the likely source, but event routing, exact normalization, CPU revision compatibility and simultaneous ownership with the Apple CPU PMU driver still need verification. This lane does not claim to have resolved the full CPMU enable sequence, width or overflow behavior, and implements no stall counter. Do not silently substitute CPU utilization for it.

### 1.3 CPU, GPU and thermal interaction

[P] `AppleCLPC_controlUpdate` (`fffffff00648b318`) takes controller maxima, limiter minima, then the domain floor. CPU domain 0 calls `AppleCLPC_applyCPUControlEffort` (`fffffff00648a03c`); SOC domain 1 calls `…648a1c0`; domain 2 calls `AppleCLPC_applyGPUFastGateEffort` (`fffffff00648a31c`).

[P] CPU effort is passed to PMGR through `fffffff005a43a08`. When the reason selects the performance-request path, `fffffff005a2bda0` converts normalized performance into a p-state using PMGR vtable +0x790, and calls `ApplePMGR_setClusterPerfState`. **CLPC can request CPU performance, not merely publish a ceiling.** PMGR still owns the effective transition and arbitration. Ghidra merges adjacent entries in this dispatcher; the argument setup and branch were checked in instruction form as well.

[P] The traced GPU-domain application votes PMGR fast-device gates using quantized effort. It does **not itself write an AGX OPP**. AGX's property handler (`fffffff006c7bbe4`) separately accepts `SetCLPCDeadlineControlEffort` and `SetCLTMPerfMax`. This establishes both CLPC and thermal policy inputs to AGX, but does not establish that the fast-gate vote alone chooses GPU frequency. [I] Preserve AGX/devfreq ownership of GPU OPP transitions in Linux.

[P] A thermal ceiling and a demand input are distinct concepts. The AGX handler exposes CLTM maximum-performance control separately from CLPC deadline effort; the CLPC common loop also has limiter objects. [I] Linux must combine demand with thermal ceilings through QoS/cooling-device arbitration, never let a demand integrator override a thermal maximum. The exact CLTM → CLPC limiter wiring and thermal thresholds were not mapped in this lane. The owner's 90/105 °C thresholds below are Linux policy requirements, not claims about Apple defaults.

## 2. Linux implementation

Working tree: Docker volume `linux-a9-src:/src/wt/clpc-1`. Branch **`a9/clpc-1`**, based directly on lane SOC `j71t-04/soc-perf` **`ab2fdae02fa3319dd014461c80e65481488eddc5`**, from repository shared with `/src/orchard04-lane-soc` (not the older Hoolock worktree repository).

Files:

- Own binding patch: `Documentation/devicetree/bindings/perf/apple,s8000-amc-pmu.yaml`.
- Driver/config patch: `drivers/perf/apple_amc_pmu.c`, `drivers/perf/Kconfig`, `drivers/perf/Makefile`.
- **Private, uncommitted** S8000 dtsi patch: a private DT patch (not published). It is applied in the build tree. This exception is required by the task's prohibition on committing dumped DT values. The branch alone therefore does not instantiate the PMU; apply the private patch before building a flight kernel. No fabricated reg range is placed in the binding.

The PMU exposes `apple_amc/{cpu_read,cpu_write,gfx_read,gfx_write}/` as byte counts. It supports system-wide counting, four simultaneous distinct fixed events, CPU-context migration on hotplug, and suspend/resume reprogramming without counting suspended time. Task-bound events, sampling and unsupported config bits are rejected. Chip selectors are match data, with no machine-compatible checks or hardware module parameters. MMIO mapping covers only the port monitor.

Each read drains all five slots under a raw spinlock and distributes byte deltas to running events. Start/stop also drain to delimit event lifetimes. A 10 ms hrtimer bounds raw-counter overflow; there is no interrupt assumption. CPU read's two slots form one perf event. Different events are read sequentially, not an atomic bank snapshot. Other AMC banks and unrelated slot enable bits are preserved. Firmware and another PMU driver must not concurrently own these five slots.

The driver deliberately has no governor, OC change or userspace control of selectors. Polling stops when no event is running. Read/clear loss and active polling overhead should be profiled after correctness; the first version prioritizes the known Apple sequence.

Build receipt and commits are recorded at the end of this document. No device test or new test suite was run by this lane.

## 3. Proposed governor — document only [I]

Use a devfreq device attached to `apple-pmgr-misc`, with two actual frequency OPPs representing states **13 / 12**. Keep PMGR's inverted numeric state IDs in driver match data; devfreq frequencies must increase with performance (do not use 13 and 12 as frequencies). `target()` maps the selected OPP to the existing state write and pending poll. Retain the static state-12 policy until this governor passes A/B flights, suspend and recovery.

A governor worker samples cumulative AMC byte counts, computes deltas over measured elapsed time, then:

```
cpu_error = (cpu_read_Bps + cpu_write_Bps) * 2^-30 - cpu_threshold
gpu_error = (gfx_read_Bps + gfx_write_Bps) * 2^-30 - gpu_threshold
E_cpu = clamp(E_cpu + cpu_error * (cpu_error > 0 ? cpu_ki_up : cpu_ki_down), 0, 1)
E_gpu = clamp(E_gpu + gpu_error * (gpu_error > 0 ? gpu_ki_up : gpu_ki_down), 0, 1)
E_stall = clamp(E_stall + (stall - target) * directional_ki, 0, 1)  # cycles != 0
E_soc = max(E_cpu, E_gpu, E_stall)
E_soc = max(floor, min(E_soc, all_applicable_limiters))
q16 = trunc(E_soc * 65536)
level = (2 * q16) / 65537
state = level ? 12 : 13
```

The quantization is significant: q16=32768 remains slow; q16=32769 goes fast. Do not approximate with `>= 0.5`. No additional hysteresis timer is present in the traced SOC path; the integrators supply hysteresis. Missing memory/fabric terms must stay absent unless configured and backed by a provider. A bandwidth-only version must be described as such until the CPU-stall provider is established.

Private policy inputs are ADT `sampling-interval-ms`, `soc-throughput-cpu-threshold`, `soc-throughput-cpu-ki-up`, `soc-throughput-cpu-ki-down`, corresponding `soc-throughput-gpu-*`, `soc-stall-target`, `soc-stall-ki-up`, `soc-stall-ki-down`. Values must be supplied through an approved private boot configuration, not copied into public source. Validate the property's fixed-point encoding against the CLPC property loader before use. Apple gains are **per sample**: do not multiply them by seconds a second time. Keep a fixed cadence; after missed samples reset the baseline/skip the update rather than applying stale deltas as a fresh sample. Real elapsed time belongs in the byte-rate calculation.

Use perf kernel consumers of the four AMC events, grouped, at the chosen uncore CPU; honor event scheduling failures and hotplug migration. Do not expose a driver-private duplicate event allocator. The shared four fixed counters imply perf tools and the governor may contend. A robust follow-up should expose a single PMU-backed cumulative sampling service for the governor or provide explicit ownership/arbitration; silently multiplexing away the governor's signal is unacceptable. At provider failure hold the release's static high state and report the loss, subject to thermal ceilings. Suspend cancels work, clears effort/baselines and requests 13; resume samples a fresh baseline before restarting. PMGR timeout is a failed transition, not successful residency.

### 3.1 Ultimate performance preset

Keep three demand domains and independent thermal maximums. AMC is a memory-pressure signal, **not** proof that raising CPU or GPU core clock helps. CPU utilization/stall/latency and hardware GPU busy time/deadline pressure must feed their own demand loops. AMC continues to choose memory state. GPU ms/frame and GPU busy %, alongside fps, assess whether an OC step helps.

Create validated CPU/GPU OC OPPs using the existing `apple_soc_cpufreq.a9_tuning` and `a9_gpu_drm.boot_gpu_oc_mhz` mechanisms as bring-up references. Production OPP transitions must preserve their voltage ordering, heartbeat/revert and recovery protections. The preset enables validated OPPs; it does not bypass limits or invent voltage tables.

At **90 °C**, reduce the allowed CPU/GPU OPP ceilings **one validated step per sample**, choosing the active power contributor first, and keep stepping down if temperature continues rising. Use separate lower-temperature hysteresis plus a sustained cool interval for one-step recovery. Determine that hysteresis and dwell from measurements, rather than importing unverified Apple constants. Anti-windup clamps/freezes the effort at the thermal ceiling so cooling does not cause an immediate full OC rebound. This replaces an unconditional drop to 1800 MHz with gradual ceilings; it must still reach stock or lower performance if required. The measured ~2160–2200 MHz sustained range is a prior observation, not a guaranteed floor.

At **105 °C**, latch the hard stop: cancel OC requests, invoke the existing emergency revert, quiesce workload, and use the kernel thermal critical action if temperature cannot be brought under control. Invalid/stale thermal samples or loss of control heartbeat also revoke OC. Do not permit automatic re-arm while latched. Thermal enforcement belongs in the kernel and remains effective if the governor worker stalls. CPU/GPU recovery must not take the SoC down.
